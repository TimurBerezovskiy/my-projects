## 3. Реалізація завдань варіанта та методи обходу

### Задача 1: Пошук максимальної зарплати
* **Метод обходу: `a` (нетипізований ітератор `Iterator`)**
* Початковим максимумом виступає платня директора.
* Через нетипізований ітератор `Iterator deptIt = departments.iterator();` обходяться відділи. Елементи отримуються як `Object` з приведенням типу `(Department)`.
* Внутрішній нетипізований ітератор `Iterator empIt = dept.getEmployees().iterator();` обходить працівників кожного відділу, порівнюючи зарплату з поточною максимальною.

### Задача 2: Пошук відділу, де працівник заробляє більше начальника
* **Метод обходу: `c` (типізований цикл «for-each»)**
* Зовнішній цикл `for (Department dept : departments)` переглядає відділи фірми.
* Внутрішній цикл `for (Employee emp : dept.getEmployees())` переглядає працівників відділу. Якщо зарплата працівника перевищує зарплату начальника `dept.getHead()`, такий відділ одразу повертається.

### Задача 3: Складання списку всіх співробітників фірми
* **Метод обходу: `b` (типізований ітератор `Iterator<T>`)**
* Створюється список `List<Employee> allEmployees = new ArrayList<>();`.
* До списку додається директор.
* За допомогою `Iterator<Department> deptIt = departments.iterator();` обходяться відділи (додається кожен начальник), а за допомогою `Iterator<Employee> empIt = dept.getEmployees().iterator();` додаються всі підлеглі працівники.

### `Firm.java`

```java
package lab07;

import java.util.ArrayList;
import java.util.Iterator;
import java.util.List;

/**
 * Лабораторна робота №7 (у методичці №10). Варіант 2.
 * Клас "Фірма" (назва, директор, список відділів).
 *
 * Студент: Березовський Тимур
 * Група: ЦК-41
 */
public class Firm {
    private String name;
    private Employee director;
    private List<Department> departments;

    public Firm(String name, Employee director) {
        this.name = name;
        this.director = director;
        this.departments = new ArrayList<>();
    }

    public String getName() {
        return name;
    }

    public Employee getDirector() {
        return director;
    }

    public List<Department> getDepartments() {
        return departments;
    }

    public void addDepartment(Department department) {
        this.departments.add(department);
    }

    /**
     * Задача 1: Знайти значення максимальної заробітної платні з усіх працівників,
     * включаючи начальників та директора.
     * Спосіб перегляду за Варіантом 2: а) нетипізований ітератор.
     */
    @SuppressWarnings("rawtypes")
    public double findMaxSalary() {
        double maxSalary = director.getSalary();

        // а) Нетипізований ітератор для обходу відділів
        Iterator deptIt = departments.iterator();
        while (deptIt.hasNext()) {
            Department dept = (Department) deptIt.next();

            // Перевіряємо зарплату начальника відділу
            if (dept.getHead() != null && dept.getHead().getSalary() > maxSalary) {
                maxSalary = dept.getHead().getSalary();
            }

            // а) Нетипізований ітератор для обходу працівників відділу
            Iterator empIt = dept.getEmployees().iterator();
            while (empIt.hasNext()) {
                Employee emp = (Employee) empIt.next();
                if (emp.getSalary() > maxSalary) {
                    maxSalary = emp.getSalary();
                }
            }
        }
        return maxSalary;
    }

    /**
     * Задача 2: Визначити відділ, в якому хоча б один з співробітників
     * отримує заробітну платню вищу за платню свого начальника.
     * Спосіб перегляду за Варіантом 2: c) типізований цикл «for-each».
     */
    public Department findDepartmentWithEmployeeEarningMoreThanHead() {
        // c) Типізований цикл for-each для відділів
        for (Department dept : departments) {
            if (dept.getHead() == null) {
                continue;
            }
            double headSalary = dept.getHead().getSalary();

            // c) Типізований цикл for-each для працівників відділу
            for (Employee emp : dept.getEmployees()) {
                if (emp.getSalary() > headSalary) {
                    return dept; // знайдено такий відділ
                }
            }
        }
        return null;
    }

    /**
     * Задача 3: Скласти список усіх співробітників фірми, включаючи начальників та директора.
     * Спосіб перегляду за Варіантом 2: b) типізований ітератор.
     */
    public List<Employee> getAllEmployees() {
        List<Employee> allEmployees = new ArrayList<>();
        if (director != null) {
            allEmployees.add(director);
        }

        // b) Типізований ітератор для відділів
        Iterator<Department> deptIt = departments.iterator();
        while (deptIt.hasNext()) {
            Department dept = deptIt.next();
            if (dept.getHead() != null) {
                allEmployees.add(dept.getHead());
            }

            // b) Типізований ітератор для працівників відділу
            Iterator<Employee> empIt = dept.getEmployees().iterator();
            while (empIt.hasNext()) {
                Employee emp = empIt.next();
                allEmployees.add(emp);
            }
        }
        return allEmployees;
    }

    @Override
    public String toString() {
        return "Фірма \"" + name + "\" (Директор: " + director.getFullName() + ")";
    }
}
```

## 6. Відповіді на контрольні питання

### 1. Для чого призначений Collections Framework?
**Java Collections Framework (JCF)** — це набір інтерфейсів, стандартних класів та готових алгоритмів у мові Java, призначений для зберігання та обробки груп об'єктів.  
Він позбавляє програміста необхідності власноруч писати низькорівневі структури даних (динамічні масиви, зв'язані списки, бінарні дерева) та надає готові, перевірені й оптимізовані реалізації (`ArrayList`, `LinkedList`, `HashSet`, `HashMap`).

---

### 2. В чому полягає різниця між масивами та колекціями?

| Критерій | Масиви (`T[]`) | Колекції (`Collection<T>`) |
| :--- | :--- | :--- |
| **Розмір** | Фіксований (не можна змінити після створення) | Динамічний (автоматично збільшується або зменшується) |
| **Типи даних** | Можуть містити і примітиви (`int`, `double`), і об'єкти | Містять **лише об'єкти** (для примітивів використовуються класи-обгортки `Integer`, `Double`) |
| **Функціонал** | Тільки доступ за індексом `arr[i]` та довжина `arr.length` | Багато готових методів: `add()`, `remove()`, `contains()`, `iterator()`, сортування |
| **Перевірка типів** | Перевірка в процесі виконання (`ArrayStoreException`) | Перевірка ще на етапі компіляції завдяки дженерикам (`List<Employee>`) |

---

### 3. Які особливі властивості є у списків порівняно з іншими типами колекцій?
Інтерфейс `List<E>` представляє **впорядковану послідовність**:
1. **Збереження порядку:** елементи завжди зберігаються у тому порядку, в якому їх додали.
2. **Доступ за числовим індексом:** можна отримати або замінити будь-який елемент за його номером: `get(index)`, `set(index, element)`.
3. **Дозвіл на дублікати:** у списку може бути кілька однакових значень (на відміну від `Set`, де всі елементи унікальні).

---

### 4. Чим списки відрізняються від масивів?
* **Гнучкість розміру:** у масив розміром 5 не можна додати 6-й елемент без створення нового масиву. Список сам виділяє додаткову пам'ять при додаванні.
* **Простота видалення:** щоб прибрати елемент з середини масиву, потрібно вручну зміщувати всі наступні елементи. У списку це робиться одним викликом `list.remove(index)`.
* **Готові алгоритми:** списки легко передаються у службові методи на кшталт `Collections.sort(list)`.

---

### 5. Чим ArrayList відрізняється від LinkedList? Який з них у яких випадках краще використовувати?

* **`ArrayList`:** побудований на звичайному внутрішньому масиві.
  * *Плюси:* миттєвий доступ до будь-якого елемента за індексом ($O(1)$) та швидке додавання в кінець. Займає мінімум пам'яті.
  * *Мінуси:* повільна вставка або видалення з середини списку, оскільки доводиться зсувати всі сусідні елементи ($O(n)$).
* **`LinkedList`:** побудований як ланцюжок вузлів, де кожен елемент пам'ятає посилання на попередній і наступний.
  * *Плюси:* дуже швидка вставка та видалення на початку списку ($O(1)$).
  * *Мінуси:* повільний доступ за індексом ($O(n)$), оскільки потрібно проходити весь ланцюжок з початку до потрібного номера. Витрачає більше пам'яті на зберігання посилань.

> **Коли що обрати:** для більшості повсякденних задач використовують `ArrayList`. `LinkedList` потрібен лише тоді, коли елементи постійно додаються та видаляються з початку списку (наприклад, у чергах).

### 6. Що таке Iterator? В чому полягають переваги використання ітератора у порівнянні з класичним циклом ”for(int i=0; i<collection.size(); i++) { /* ... */ }”?

**`Iterator`** — це спеціальний об'єкт, який дозволяє по черзі пройтися по всіх елементах колекції, не знаючи, як саме вона влаштована всередині.

**Переваги над індексним циклом:**
1. Працює для будь-яких колекцій (наприклад, у множинах `Set` чи картах взагалі немає номерів за індексом, тому циклом `for (int i...)` їх обійти неможливо, а ітератором — можна).
2. На `LinkedList` класичний цикл `for (int i...)` працює вкрай повільно ($O(n^2)$), оскільки для кожного `i` переглядає весь список з початку. Ітератор проходить його швидко за один прохід ($O(n)$).
3. Дозволяє безпечно видаляти елементи під час самого обходу через `iterator.remove()`, уникаючи помилки `ConcurrentModificationException`.

### 7. Що таке типізовані та нетипізовані колекції?

* **Нетипізовані колекції (до появи Java 5):**
  Оголошуються просто як `List list = new ArrayList();`. Вони приймають будь-які об'єкти (`Object`), через що при отриманні елемента його обов'язково треба вручну приводити до потрібного типу: `Employee e = (Employee) list.get(0);`. Якщо туди випадково потрапить інший об'єкт, програма впаде з помилкою `ClassCastException`.
* **Типізовані колекції (Generics):**
  Оголошуються із зазначенням конкретного типу: `List<Employee> list = new ArrayList<>();`. Компілятор одразу перевіряє типи та не дозволить покласти в список сторонній об'єкт, а при читанні приведення типів не потрібне: `Employee e = list.get(0);`.

---

### 8. Для чого потрібен інтерфейс RandomAccess?
`RandomAccess` — це інтерфейс-маркер (він не містить жодного методу). Він слугує позначкою для алгоритмів, що дана колекція підтримує миттєвий прямий доступ до будь-якого елемента за $O(1)$.
* `ArrayList` має цю позначку, бо він побудований на масиві.
* `LinkedList` її не має, бо для пошуку елемента треба йти по ланцюжку.

Завдяки цьому стандартні методи (наприклад, бінарний пошук або сортування) знають, який спосіб обходу обрати для максимальної швидкодії.

---

### 9. Чим Collection відрізняється від Collections?

* **`Collection` (в однині)** — це базовий **інтерфейс**, від якого походять основні колекції (`List`, `Set`, `Queue`). Він задає основні методи: `add()`, `remove()`, `size()`, `clear()`.
* **`Collections` (у множині)** — це допоміжний **клас**, який містить готові статичні методи для роботи зі списками та колекціями: наприклад, сортування `Collections.sort()`, пошук максимуму `Collections.max()`, розгортання `Collections.reverse()`.
