## 2. Завдання №2

### Умова
> **Знайти суму елементів, що більші 3**

### Як я це робив
1. **Вибір циклу:** За вимогами лабораторної роботи в одному з завдань обов'язково має бути використаний цикл «for-each». Оскільки в цій задачі не потрібні індекси елементів і масив лише зчитується, цикл `for-each` ідеально підходить саме для цього завдання.
2. **Тип даних:** Для універсальності використано масив дійсних чисел `double[]`.
3. **Валідація вхідних даних:**
   - Якщо посилання на масив є `null`, викидається `NullPointerException`.
   - Якщо масив порожній (`array.length == 0`), викидається `IllegalArgumentException`.
   - Якщо в масиві зустрічається значення `Double.NaN`, також викидається `IllegalArgumentException`.
4. **Обчислення:**
   - Ініціалізується акумулятор `sum = 0.0`.
   - За допомогою `for (double element : array)` перебираються всі елементи; якщо `element > 3.0`, значення додається до суми.

### Код програми (`Task2.java`)
```java
package lab04;

import java.util.Arrays;

public class Task2 {

    public static void main(String[] args) {
        System.out.println("=== ТЕСТУВАННЯ ЗАВДАННЯ 2 (for-each) ===");
        System.out.println("Знайти суму елементів, що більші 3:\n");

        // Дозволені комбінації аргументів
        printResults(new double[]{1.5, 4.0, 2.8, 5.5, 3.0, 10.2});
        printResults(new double[]{-2.0, 0.0, 1.0, 2.9, 3.0});
        printResults(new double[]{3.0001, 3.5, 100.0});
        printResults(new double[]{-10.5, 7.2, -3.1, 4.8, 1.0});
        printResults(new double[]{10.0});
        printResults(new double[]{2.0});

        System.out.println("\n--- Заборонені комбінації (обробка виключень) ---");
        // Заборонені комбінації (null, порожній масив, NaN)
        printResults(null);
        printResults(new double[]{});
        printResults(new double[]{4.5, Double.NaN, 6.0});
    }

    /**
     * Знаходить суму елементів масиву, які строго більші за 3.
     * За умовою лабораторної роботи використано цикл «for-each».
     *
     * @param array масив дійсних чисел
     * @return сума елементів, більших за 3
     * @throws NullPointerException якщо передано null
     * @throws IllegalArgumentException якщо масив порожній або містить NaN
     */
    public static double sumGreaterThanThree(double[] array) {
        if (array == null) {
            throw new NullPointerException("Масив не може бути null");
        }
        if (array.length == 0) {
            throw new IllegalArgumentException("Масив не може бути порожнім");
        }

        double sum = 0.0;
        // Обов'язкове використання циклу for-each згідно з вимогами ЛР
        for (double element : array) {
            if (Double.isNaN(element)) {
                throw new IllegalArgumentException("Елемент масиву не може бути NaN");
            }
            if (element > 3.0) {
                sum += element;
            }
        }
        return sum;
    }

    static void printResults(double[] array) {
        String arrayStr = (array == null) ? "null" : Arrays.toString(array);
        System.out.print("Масив: " + arrayStr + " -> Результат: ");
        try {
            double result = sumGreaterThanThree(array);
            System.out.println(result);
        } catch (NullPointerException | IllegalArgumentException e) {
            System.out.println("EXCEPTION! " + e.getClass().getSimpleName() + ": " + e.getMessage());
        }
    }
}
```

## 3. Завдання №32

### Умова
> **Знайти суму парних елементів масиву, що стоять на непарних місцях**

### Як я це робив
1. **Вибір циклу:** Застосовано стандартний цикл `for` з індексами (обов'язкова вимога лабораторної).
2. **Аналіз поняття «непарні місця»:**
   - У математичному та загальномовному розумінні місця (позиції) нумеруються людиною починаючи з 1:
     - 1-е місце $\to$ індекс `0` (непарне місце)
     - 2-е місце $\to$ індекс `1` (парне місце)
     - 3-є місце $\to$ індекс `2` (непарне місце)
     - 4-е місце $\to$ індекс `3` (парне місце)
     - тощо. Тобто непарні місця відповідають парним індексам `i = 0, 2, 4...`.
   - Проте в розмовній мові програмістів термін «непарні місця» іноді вживають як синонім до «непарні індекси» (`i = 1, 3, 5...`).
   - Щоб код був максимально надійним і гнучким, я реалізував підтримку обох підходів через параметр `oneBasedPlaces` (за замовчуванням `true` — нумерація місць з 1).
3. **Парність чисел:** Число є парним, якщо остача від ділення на 2 дорівнює 0 (`array[i] % 2 == 0`). Це правило коректно працює як для додатних, так і для від'ємних парних чисел, а також для нуля.
4. **Валідація:** Перевірка на `null` (`NullPointerException`) та порожній масив (`IllegalArgumentException`).

### Код програми (`Task32.java`)

```java
package lab04;

import java.util.Arrays;

public class Task32 {

    public static void main(String[] args) {
        System.out.println("=== ТЕСТУВАННЯ ЗАВДАННЯ 32 (цикл for) ===");
        System.out.println("Знайти суму парних елементів масиву, що стоять на непарних місцях:\n");

        // 1. Тести за стандартним математичним розумінням "непарних місць" (нумерація з 1: 1-е, 3-є, 5-те місця -> індекси 0, 2, 4...)
        System.out.println("--- Варіант А: Нумерація місць з 1 (1-е, 3-є, 5-те місця -> індекси 0, 2, 4...) ---");
        printResults(new int[]{4, 3, 6, 7, 8, 9}, true);
        printResults(new int[]{1, 2, 3, 4, 5, 6}, true);
        printResults(new int[]{-4, 10, -2, 5, 0, 11}, true);
        printResults(new int[]{2}, true);
        printResults(new int[]{3}, true);

        // 2. Тести за розумінням як "непарні індекси" (індекси 1, 3, 5...)
        System.out.println("\n--- Варіант Б: За непарними індексами (індекси 1, 3, 5...) ---");
        printResults(new int[]{4, 3, 6, 7, 8, 9}, false);
        printResults(new int[]{1, 2, 3, 4, 5, 6}, false);
        printResults(new int[]{1, -8, 3, -4, 5, 0}, false);

        System.out.println("\n--- Заборонені комбінації (обробка виключень) ---");
        printResults(null, true);
        printResults(new int[]{}, true);
    }

    /**
     * Знаходить суму парних елементів масиву, що стоять на непарних місцях.
     * За замовчуванням розглядаються місця за порядковим номером (нумерація з 1: 1-ше, 3-тє, 5-те... тобто індекси 0, 2, 4...).
     *
     * @param array масив цілих чисел
     * @return сума парних елементів на непарних місцях
     * @throws NullPointerException якщо масив null
     * @throws IllegalArgumentException якщо масив порожній
     */
    public static int sumEvenAtOddPlaces(int[] array) {
        return sumEvenAtOddPlaces(array, true);
    }

    /**
     * Знаходить суму парних елементів масиву, що стоять на непарних місцях.
     * За умовою лабораторної роботи використано цикл «for».
     *
     * @param array масив цілих чисел
     * @param oneBasedPlaces true — нумерація місць з 1 (індекси 0, 2, 4...), false — непарні індекси (індекси 1, 3, 5...)
     * @return сума парних чисел на обраних позиціях
     * @throws NullPointerException якщо масив null
     * @throws IllegalArgumentException якщо масив порожній
     */
    public static int sumEvenAtOddPlaces(int[] array, boolean oneBasedPlaces) {
        if (array == null) {
            throw new NullPointerException("Масив не може бути null");
        }
        if (array.length == 0) {
            throw new IllegalArgumentException("Масив не може бути порожнім");
        }

        int sum = 0;
        int startIndex = oneBasedPlaces ? 0 : 1;

        // Обов'язкове використання звичайного циклу for з індексами
        for (int i = startIndex; i < array.length; i += 2) {
            // Перевірка на парність елемента (ділиться на 2 без остачі)
            if (array[i] % 2 == 0) {
                sum += array[i];
            }
        }
        return sum;
    }

    static void printResults(int[] array, boolean oneBasedPlaces) {
        String arrayStr = (array == null) ? "null" : Arrays.toString(array);
        String modeStr = oneBasedPlaces ? "місця 1, 3, 5..." : "індекси 1, 3, 5...";
        System.out.print("Масив: " + arrayStr + " (" + modeStr + ") -> Результат: ");
        try {
            int result = sumEvenAtOddPlaces(array, oneBasedPlaces);
            System.out.println(result);
        } catch (NullPointerException | IllegalArgumentException e) {
            System.out.println("EXCEPTION! " + e.getClass().getSimpleName() + ": " + e.getMessage());
        }
    }
}
```

## 4. Завдання №62

### Умова
> **Задано масив цілих чисел. Сформувати новий масив у наступний спосіб: поділити усі елементи масиву на його найменший елемент, якщо найменший елемент відмінний від нуля; якщо ж найменший елемент дорівнює нулю, то всі елементи масиву замінити на -10.**

### Як я це робив
1. **Алгоритм рішення:**
   - **Крок 1:** Перевіряю валідність вхідного масиву (`null` або порожній).
   - **Крок 2:** Знаходжу найменший елемент `min` масиву. Пошук реалізовано за допомогою циклу `for-each`.
   - **Крок 3:** Створюю **новий масив** точно такого ж розміру `array.length`. Оригінальний масив залишається без змін (незмінність вхідних даних — імутабельність).
   - **Крок 4:** Перевіряю умову `min == 0`:
     - Якщо `min == 0`: заповнюю всі елементи нового масиву значенням `-10.0`.
     - Якщо `min != 0`: ділю кожен елемент масиву на `min`.
2. **Точність ділення:** Оскільки результат ділення цілих чисел взагалі кажучи не є цілим числом (наприклад $3 / 2 = 1.5$), основний метод `transformArray` повертає масив типу `double[]`, що зберігає точні дійсні результати ділення. Також додатково реалізовано метод `transformArrayInt` для випадку цілочисельного ділення.

### Код програми (`Task62.java`)
```java
package lab04;

import java.util.Arrays;

public class Task62 {

    public static void main(String[] args) {
        System.out.println("=== ТЕСТУВАННЯ ЗАВДАННЯ 62 ===");
        System.out.println("Сформувати новий масив: поділити на min (якщо min != 0), або замінити на -10 (якщо min == 0):\n");

        // Дозволені випадки:
        // 1. min > 0 (ділення націло)
        printResults(new int[]{4, 2, 6, 8, 10});

        // 2. min > 0 (ділення з дробовою частиною)
        printResults(new int[]{3, 5, 7, 2});

        // 3. min == 0 (усі елементи мають стати -10)
        printResults(new int[]{5, 0, 12, 3, 8});

        // 4. min < 0 (від'ємний мінімум)
        printResults(new int[]{10, -5, 20, -10, 15});

        // 5. Одноклітинний масив
        printResults(new int[]{5});
        printResults(new int[]{0});

        System.out.println("\n--- Заборонені комбінації (обробка виключень) ---");
        printResults(null);
        printResults(new int[]{});
    }

    /**
     * Формує новий масив: ділить усі елементи на найменший елемент (якщо min != 0),
     * або замінює всі елементи на -10 (якщо min == 0).
     * Оригінальний масив не змінюється.
     *
     * @param array вхідний масив цілих чисел
     * @return новий сформований масив дійсних чисел (зберігає точність ділення)
     * @throws NullPointerException якщо масив null
     * @throws IllegalArgumentException якщо масив порожній
     */
    public static double[] transformArray(int[] array) {
        if (array == null) {
            throw new NullPointerException("Масив не може бути null");
        }
        if (array.length == 0) {
            throw new IllegalArgumentException("Масив не може бути порожнім");
        }

        // 1. Пошук найменшого елемента масиву за допомогою for-each
        int min = array[0];
        for (int value : array) {
            if (value < min) {
                min = value;
            }
        }

        // 2. Створення нового масиву необхідної розмірності
        double[] result = new double[array.length];

        // 3. Заповнення нового масиву за умовами завдання
        if (min == 0) {
            for (int i = 0; i < array.length; i++) {
                result[i] = -10.0;
            }
        } else {
            for (int i = 0; i < array.length; i++) {
                result[i] = (double) array[i] / min;
            }
        }

        return result;
    }

    /**
     * Варіант методу з цілочисельним діленням (int[] -> int[]).
     */
    public static int[] transformArrayInt(int[] array) {
        if (array == null) {
            throw new NullPointerException("Масив не може бути null");
        }
        if (array.length == 0) {
            throw new IllegalArgumentException("Масив не може бути порожнім");
        }

        int min = array[0];
        for (int value : array) {
            if (value < min) {
                min = value;
            }
        }

        int[] result = new int[array.length];
        if (min == 0) {
            for (int i = 0; i < array.length; i++) {
                result[i] = -10;
            }
        } else {
            for (int i = 0; i < array.length; i++) {
                result[i] = array[i] / min;
            }
        }
        return result;
    }

    static void printResults(int[] array) {
        String arrayStr = (array == null) ? "null" : Arrays.toString(array);
        System.out.print("Вхідний масив: " + arrayStr + " -> ");
        try {
            double[] result = transformArray(array);
            System.out.println("Результат: " + Arrays.toString(result));
        } catch (NullPointerException | IllegalArgumentException e) {
            System.out.println("EXCEPTION! " + e.getClass().getSimpleName() + ": " + e.getMessage());
        }
    }
}
```

## 5. Відповіді на контрольні питання

### 1. Чим змінна відрізняється від масиву?
* **Змінна** (примітивного типу або одиничне посилання) зберігає рівно **одне значення** певного типу даних у виділеній комірці оперативної пам'яті (наприклад, `int x = 5;`).
* **Масив** — це впорядкована структура даних фіксованого розміру, яка зберігає **сукупність однотипних елементів** у неперервній ділянці пам'яті. Звернення до окремих комірок масиву здійснюється за їхнім числовим індексом за постійний час $O(1)$. Масив сам по собі є повноцінним посилальним об'єктом.

---

### 2. Що таке стек? Що таке купа? Яка між ними різниця?
* **Стек (Stack Memory):**
  * Структура даних пам'яті, що працює за принципом **LIFO** (*Last In, First Out* — останнім прийшов, першим пішов).
  * Кожен потік виконання Java має власний стек.
  * У стеку створюються та зберігаються **стекові кадри (stack frames)** під час виклику кожного методу. У цих кадрах містяться локальні примітивні змінні, посилання на об'єкти в купі та адреси повернення.
  * Виділення і звільнення пам'яті в стеку відбувається автоматично й миттєво під час входу в метод та виходу з нього (зсувом покажчика стека).
* **Купа (Heap Memory):**
  * Загальна динамічна область пам'яті для всього застосунку Java.
  * У купі виділяється місце під **усі об'єкти та масиви**, створені оператором `new`.
  * Життєвий цикл об'єктів у купі не прив'язаний до виклику методів — об'єкти існують доти, доки на них є посилання, і видаляються автоматичним збирачем сміття (**Garbage Collector**).
* **Основні відмінності:**
  | Критерій | Стек (Stack) | Купа (Heap) |
  | :--- | :--- | :--- |
  | **Що зберігає** | Локальні примітивні змінні, посилання | Усі об'єкти та масиви |
  | **Швидкість** | Дуже висока | Повільніша, ніж стек |
  | **Доступність** | Ізольований для кожного потоку | Спільна для всіх потоків |
  | **Керування пам'яттю** | Автоматично процесором (LIFO) | Збирач сміття (Garbage Collector) |
  | **Помилка переповнення** | `StackOverflowError` | `OutOfMemoryError` |

---

### 3. Чи може змінна бути розташована у стеку? Безпосередньо у купі? В об’єкті у купі? Чи може масив бути розташований у стеку? Безпосередньо у купі? В об’єкті у купі?
* **Щодо змінної:**
  * **У стеку:** **ТАК.** Будь-яка локальна змінна методу (як примітивного типу, так і змінна-посилання) розташовується у стековому кадрі поточного виклику.
  * **Безпосередньо у купі:** **НІ.** Змінні самі по собі автономно в купі не існують — пам'ять у купі завжди виділяється під структури даних (об'єкти або масиви).
  * **В об’єкті у купі:** **ТАК.** Усі поля класу (як примітивні типи, так і посилання на інші об'єкти) фізично розміщуються всередині тіла об'єкта, що зберігається в купі.
* **Щодо масиву:**
  * **У стеку:** **НІ.** Масив у мові Java є повноцінним об'єктом, тому сам масив (його тіло та комірки) **завжди** розміщується виключно в купі (Heap). У стеку може перебувати лише посилання на цей масив.
  * **Безпосередньо у купі:** **ТАК.** Коли створюється масив (наприклад, `new int[10]`), він розміщується в купі як окремий самостійний блок пам'яті.
  * **В об’єкті у купі:** Формально об'єкт містить **посилання** на масив, а сам масив виділяється як окремий об'єкт у купі, на який посилається поле класу.

---

### 4. Чим посилання на масив відрізняється від масиву? Чи може посилання на масив бути розташовано у стеку? Безпосередньо у купі? В об’єкті у купі?
* **Відмінність:**
  * **Масив** — це реальний об'єкт у купі, що містить заголовок, поле довжини `length` та послідовність комірок пам'яті зі значеннями.
  * **Посилання на масив** — це 32- або 64-бітна змінна (адреса покажчика), що лише вказує на місцезнаходження масиву в купі. Копіювання посилання копіює лише адресу, а не сам масив.
* **Розташування посилання на масив:**
  * **У стеку:** **ТАК** — як локальна змінна методу (наприклад, `int[] arr = new int[5];`).
  * **Безпосередньо у купі:** **ТАК** — як елемент масиву посилань (наприклад, рядки багатовимірного масиву `int[][]` є посиланнями на одновимірні масиви, що лежать у купі).
  * **В об’єкті у купі:** **ТАК** — як поле екземпляра класу (`class Company { Employee[] staff; }`).

---

### 5. Якщо масив складається з 10 комірок, які індекси мають перша та остання комірки?
* У мові Java нумерація елементів масиву завжди починається з нуля (**0-based indexing**).
* **Перша комірка** має індекс **`0`**.
* **Остання комірка** має індекс **`9`** (обчислюється як $\text{довжина} - 1$, тобто $10 - 1 = 9$).

---

### 6. Що буде, якщо звернутися до неіснуючої комірки у масиві?
* Віртуальна машина Java (JVM) виконує автоматичну перевірку меж масиву (*bounds checking*) під час кожного звернення.
* Якщо переданий індекс є від'ємним ($< 0$) або перевищує допустимий максимум ($\ge \text{array.length}$), негайно генерується виключення часу виконання:
  $$\mathbf{ArrayIndexOutOfBoundsException}$$
* Якщо це виключення не обробити в блоці `try-catch`, виконання поточного потоку негайно аварійно переривається.

---

### 7. При створенні нового масиву без явної ініціалізації усі його комірки будуть проініціалізовані: спеціальними значеннями за замовчуванням? чи довільними значеннями з пам’яті?
* Усі комірки нового масиву в Java **гарантовано ініціалізуються спеціальними значеннями за замовчуванням (Default Values)**.
* На відміну від мов C/C++, у Java виділена пам'ять обов'язково автоматично зануляється JVM з міркувань безпеки:
  * Для цілих типів (`byte`, `short`, `int`, `long`): значення **`0`** (або `0L`).
  * Для дійсних чисел (`float`, `double`): значення **`0.0f`** / **`0.0d`**.
  * Для символів (`char`): нуль-символ **`'\u0000'`** (код 0).
  * Для логічного типу (`boolean`): значення **`false`**.
  * Для будь-яких об'єктних посилань (`String`, класи, вкладені масиви): значення **`null`**.
* Отримання «довільного сміття» з пам'яті в Java є неможливим.

---

### 8. Як дізнатися номер першої та останньої комірки масиву, якщо відомо лише посилання на нього?
* **Номер першої комірки:** Завжди дорівнює **`0`** (якщо масив непорожній, тобто `array.length > 0`).
* **Номер останньої комірки:** Визначається через незмінну публічну властивість довжини масиву:  
  $$\mathbf{array.length - 1}$$
* *Важливе зауваження:* Якщо масив порожній (`array.length == 0`), він не містить жодної комірки, тому звернення до індексу `0` викличе `ArrayIndexOutOfBoundsException`. Перед зверненням завжди варто перевірити: `if (array != null && array.length > 0)`.

---

### 9. Як змінити розмір масиву?
* **Фізично змінити розмір існуючого масиву в Java НЕМОЖЛИВО.** Розмір масиву є константним від моменту створення в пам'яті купи.
* Щоб отримати масив іншого розміру з тими самими даними, створюють **новий масив** бажаного розміру і копіюють у нього елементи зі старого:
  1. За допомогою стандартного методу:
     ```java
     int[] newArray = Arrays.copyOf(oldArray, newSize);
     ```
  2. За допомогою високоефективного системного нативного виклику:
     ```java
     System.arraycopy(oldArray, 0, newArray, 0, oldArray.length);
     ```
  3. Звичайним поелементним копіюванням через цикл `for`.
* Якщо задача вимагає частої та динамічної зміни кількості елементів, замість масивів використовують колекції, наприклад `java.util.ArrayList`.

---

### 10. Що відбувається з масивом при копіюванні посилання на нього?
* При операції присвоєння посилань (наприклад, `int[] b = a;`) копіюється лише **адреса посилання**, а **не сам масив**.
* Новий масив у купі **не створюється**.
* Обидві змінні (`a` та `b`) починають вказувати на **один і той самий фізичний об'єкт масиву** в оперативній пам'яті.
* Зміна будь-якого елемента через одне посилання (`b[0] = 99;`) миттєво відображається через інше посилання (`a[0]` поверне 99), оскільки дані зберігаються в єдиному спільному екземплярі.

---

### 11. Що відбувається з масивом при втрачанні посилання на нього?
* Якщо на об'єкт масиву в купі більше не вказує жодне активне посилання (наприклад, єдиній змінній присвоїли `null`, метод завершив роботу і стековий кадр знищився, або посиланню призначили інший масив), масив переходить у статус **недосяжного (unreachable)**.
* Такий масив маркується як сміття і під час наступного запуску **Garbage Collector (GC)** його буде вилучено з пам'яті купи, а займані байти пам'яті повернено системі для нових виділень.

---

### 12. Чим відрізняються конструкції «for» та «for-each» при роботі з масивами? Які переваги та недоліки кожного з варіантів?

| Характеристика | Звичайний цикл `for` | Покращений цикл `for-each` |
| :--- | :--- | :--- |
| **Синтаксис** | `for (int i = 0; i < arr.length; i++)` | `for (int element : arr)` |
| **Наявність індексу** | Є повний доступ до індексу `i` | Індекс відсутній |
| **Зміна значень у масиві** | **Можлива** (`arr[i] = value;`) | **Неможлива** (змінна `element` є локальною копією значення) |
| **Порядок та крок обходу** | Довільний (прямий, зворотний, крок 2, 3...) | Тільки послідовно від першого до останнього з кроком 1 |
| **Одночасна робота з кількома масивами** | Можлива через спільний індекс `i` | Неможлива (ітерується лише один масив) |
| **Безпека меж масиву** | Можлива помилка виходу за межі (`ArrayIndexOutOfBoundsException`) | Гарантована відсутність виходу за межі |
| **Читабельність коду** | Більш громіздкий, вимагає ініціалізації та умови | Лаконічний, компактний і зрозумілий |

---

### 13. Чи можна у масив «double[]» записати значення «int»? Чи можна у масив «int[]» записати значення «double»?
* **У масив `double[]` записати `int` — ТАК, МОЖНА.**
  * Це дозволено синтаксисом Java завдяки автоматичному **неявному розширенню типів (Widening Primitive Conversion)**.
  * Оскільки тип `double` (64 біти) ширший за `int` (32 біти), значення цілого числа автоматично перетворюється на дійсне без втрати даних чи попереджень компілятора:
    ```java
    double[] d = new double[3];
    int x = 42;
    d[0] = x; // Успішно скомпілюється: значення стане 42.0
    ```
* **У масив `int[]` записати `double` — НІ, НАПРЯМУ НЕ МОЖНА.**
  * Спроба прямого запису викличе **помилку компіляції**:  
    `error: incompatible types: possible lossy conversion from double to int`
  * Компілятор Java забороняє автоматичне звуження типів, оскільки при відкиданні дробової частини втрачається точність.
  * Записати значення можна лише за допомогою **явного приведення типів (Narrowing Explicit Casting)**, при якому дробова частина буде відкинута (усічена до нуля):
    ```java
    int[] a = new int[3];
    double pi = 3.14159;
    a[0] = (int) pi; // Явне приведення: у комірку запишеться число 3
    ```
