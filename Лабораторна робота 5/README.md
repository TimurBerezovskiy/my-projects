## 2. Метод 1: Сортування вибором (Selection Sort)

### Умова
> Реалізувати алгоритм сортування вибором (**Selection sort**) для одновимірного масиву типу `short[]` за спаданням.

### Як я це робив
1. Для сортування за спаданням на кожній ітерації потрібно знаходити найбільший елемент серед невідсортованої частини і переставляти його на початок цієї частини.
2. Зовнішній цикл `for (int i = 0; i < n - 1; i++)` фіксує поточну позицію `i`, куди має стати черговий максимум.
3. У внутрішньому циклі `for (int j = i + 1; j < n; j++)` я проходжуся по невідсортованому залишку масиву і знаходжу індекс найбільшого числа `maxIndex`.
4. Якщо знайдений максимум не стоїть на поточному місці (`maxIndex != i`), змінюю елементи місцями через допоміжну змінну `temp`.
5. Зробив перевірку на `null`: якщо передано `null`, викидається виключення `NullPointerException`. Для порожнього масиву та масиву з одного елемента сортування не потрібне, тому метод одразу завершує роботу.
6. Для зручності тестування зробив метод `sortCopy`, який копіює вхідний масив і сортує вже копію, щоб початковий масив не змінювався при виведенні на екран. Також додав метод `sortWithTracing` для наочного покрокового виведення проміжних станів масиву.

### Код програми (`SelectionSort.java`)
```java
package lab05;

import java.util.Arrays;

/**
 * Лабораторна робота №5. Варіант 2.
 * Метод 1: Сортування вибором (Selection sort) для масиву short[] за спаданням.
 */
public class SelectionSort {

    public static void main(String[] args) {
        System.out.println("=== Сортування вибором (Selection sort) ===");
        System.out.println("Порядок: по спаданню | Тип: short[]\n");

        // Тести на коректних даних
        printResults(new short[]{5, -2, 18, 0, 42, -9, 7});
        printResults(new short[]{50, 40, 30, 20, 10, 0, -10});
        printResults(new short[]{-15, -5, 0, 12, 34, 89});
        printResults(new short[]{7, 3, 7, 1, 3, 7, 0});
        printResults(new short[]{5, 5, 5, 5});
        printResults(new short[]{0, Short.MAX_VALUE, -100, Short.MIN_VALUE, 1234});
        printResults(new short[]{42});
        printResults(new short[]{});

        System.out.println("\n--- Обробка помилок ---");
        printResults(null);

        System.out.println("\n--- Покрокова робота алгоритму ---");
        short[] demo = {12, 45, -3, 89, 0, 21};
        System.out.println("Початковий масив: " + Arrays.toString(demo));
        sortWithTracing(demo);
    }

    /**
     * Сортування масиву short[] за спаданням методом вибору на місці.
     */
    public static void sort(short[] array) {
        if (array == null) {
            throw new NullPointerException("Масив не може бути null");
        }
        if (array.length <= 1) {
            return;
        }

        int n = array.length;
        for (int i = 0; i < n - 1; i++) {
            int maxIndex = i;
            // шукаємо індекс найбільшого елемента в невідсортованій частині
            for (int j = i + 1; j < n; j++) {
                if (array[j] > array[maxIndex]) {
                    maxIndex = j;
                }
            }
            // якщо знайшли більший елемент — міняємо місцями
            if (maxIndex != i) {
                short temp = array[i];
                array[i] = array[maxIndex];
                array[maxIndex] = temp;
            }
        }
    }

    public static short[] sortCopy(short[] array) {
        if (array == null) {
            throw new NullPointerException("Масив не може бути null");
        }
        short[] copy = Arrays.copyOf(array, array.length);
        sort(copy);
        return copy;
    }

    public static void sortWithTracing(short[] array) {
        if (array == null) return;
        int n = array.length;
        int step = 1;
        for (int i = 0; i < n - 1; i++) {
            int maxIndex = i;
            for (int j = i + 1; j < n; j++) {
                if (array[j] > array[maxIndex]) {
                    maxIndex = j;
                }
            }
            if (maxIndex != i) {
                short temp = array[i];
                array[i] = array[maxIndex];
                array[maxIndex] = temp;
                System.out.printf("Крок %d: max=%d на індексі %d -> обмін з індексом %d: %s%n",
                        step++, array[i], maxIndex, i, Arrays.toString(array));
            } else {
                System.out.printf("Крок %d: max=%d вже на індексі %d: %s%n",
                        step++, array[i], i, Arrays.toString(array));
            }
        }
        System.out.println("Результат: " + Arrays.toString(array));
    }

    static void printResults(short[] array) {
        String str = (array == null) ? "null" : Arrays.toString(array);
        System.out.print("Масив: " + str + " -> ");
        try {
            short[] sorted = sortCopy(array);
            System.out.println("Результат: " + Arrays.toString(sorted));
        } catch (NullPointerException e) {
            System.out.println("EXCEPTION! " + e.getClass().getSimpleName() + ": " + e.getMessage());
        }
    }
}
```

## 3. Метод 2: Сортування вставкою (Insertion Sort)

### Умова
> Реалізувати алгоритм сортування вставкою (**Insertion sort**) для одновимірного масиву типу `short[]` за спаданням.

### Як я це робив
1. Вважаємо, що перший елемент (з індексом `0`) уже утворює відсортовану частину масиву довжиною 1.
2. Зовнішній цикл починається з другого елемента (`for (int i = 1; i < n; i++)`). Значення елемента зберігаю у змінну `key`.
3. У внутрішньому циклі `while (j >= 0 && array[j] < key)` я порівнюю `key` з елементами ліворуч. Оскільки ми сортуємо по спаданню, усі елементи, які менші за `key`, зсуваю праворуч на одну клітинку (`array[j + 1] = array[j]`).
4. Як тільки цикл зупиняється (знайшли елемент не менший за `key` або дійшли до початку), записую `key` у звільнену комірку `array[j + 1]`.
5. Умова `array[j] < key` є строгою, завдяки чому однакові елементи не міняються місцями — сортування є стабільним.
6. Метод також містить перевірку на `null` (`NullPointerException`) та коректно опрацьовує масиви довжиною 0 або 1.

### Код програми (`InsertionSort.java`)
```java
package lab05;

import java.util.Arrays;

/**
 * Лабораторна робота №5. Варіант 2.
 * Метод 2: Сортування вставкою (Insertion sort) для масиву short[] за спаданням.
 */
public class InsertionSort {

    public static void main(String[] args) {
        System.out.println("=== Сортування вставкою (Insertion sort) ===");
        System.out.println("Порядок: по спаданню | Тип: short[]\n");

        // Тести на коректних даних
        printResults(new short[]{5, -2, 18, 0, 42, -9, 7});
        printResults(new short[]{50, 40, 30, 20, 10, 0, -10});
        printResults(new short[]{-15, -5, 0, 12, 34, 89});
        printResults(new short[]{50, 45, 10, 30, 25, 20, 5});
        printResults(new short[]{7, 3, 7, 1, 3, 7, 0});
        printResults(new short[]{8, 8, 8, 8});
        printResults(new short[]{0, Short.MAX_VALUE, -100, Short.MIN_VALUE, 1234});
        printResults(new short[]{42});
        printResults(new short[]{});

        System.out.println("\n--- Обробка помилок ---");
        printResults(null);

        System.out.println("\n--- Покрокова робота алгоритму ---");
        short[] demo = {12, 45, -3, 89, 0, 21};
        System.out.println("Початковий масив: " + Arrays.toString(demo));
        sortWithTracing(demo);
    }

    /**
     * Сортування масиву short[] за спаданням методом вставки на місці.
     */
    public static void sort(short[] array) {
        if (array == null) {
            throw new NullPointerException("Масив не може бути null");
        }
        if (array.length <= 1) {
            return;
        }

        for (int i = 1; i < array.length; i++) {
            short key = array[i];
            int j = i - 1;

            // Зсуваємо праворуч елементи, які менші за key
            while (j >= 0 && array[j] < key) {
                array[j + 1] = array[j];
                j--;
            }
            array[j + 1] = key;
        }
    }

    public static short[] sortCopy(short[] array) {
        if (array == null) {
            throw new NullPointerException("Масив не може бути null");
        }
        short[] copy = Arrays.copyOf(array, array.length);
        sort(copy);
        return copy;
    }

    public static void sortWithTracing(short[] array) {
        if (array == null) return;
        int n = array.length;
        for (int i = 1; i < n; i++) {
            short key = array[i];
            int j = i - 1;
            int shifts = 0;

            while (j >= 0 && array[j] < key) {
                array[j + 1] = array[j];
                j--;
                shifts++;
            }
            array[j + 1] = key;

            System.out.printf("Крок %d: вставка key=%d (зсувів: %d) -> %s%n",
                    i, key, shifts, Arrays.toString(array));
        }
        System.out.println("Результат: " + Arrays.toString(array));
    }

    static void printResults(short[] array) {
        String str = (array == null) ? "null" : Arrays.toString(array);
        System.out.print("Масив: " + str + " -> ");
        try {
            short[] sorted = sortCopy(array);
            System.out.println("Результат: " + Arrays.toString(sorted));
        } catch (NullPointerException e) {
            System.out.println("EXCEPTION! " + e.getClass().getSimpleName() + ": " + e.getMessage());
        }
    }
}
```

## 4. Відповіді на контрольні питання

### 1. Порівняйте та назвіть переваги та недоліки таких методів сортування: сортування бульбашкою, сортування вибором, сортування вставкою.

Усі три методи є простими алгоритмами сортування порівняннями, які працюють за час $O(n^2)$ у середньому та найгіршому випадках і сортують масив на місці ($O(1)$ пам'яті):

* **Сортування бульбашкою (Bubble sort):**
  * *Переваги:* дуже простий для розуміння та написання; є стабільним алгоритмом; якщо додати прапорець перевірки обмінів, то на вже відсортованому масиві завершується за лінійний час $O(n)$.
  * *Недоліки:* робить найбільше операцій swap (до $\frac{n(n-1)}{2}$), через що є найповільнішим на практиці; має проблему «черепах» (значення з кінця масиву рухаються на початок дуже повільно).
* **Сортування вибором (Selection sort):**
  * *Переваги:* робить **мінімальну кількість обмінів** серед простих методів — не більше $n - 1$ обмінів за весь час роботи ($O(n)$ записів у пам'ять); підходить для ситуацій, де запис у пам'ять є ресурсомістким (наприклад, Flash-пам'ять).
  * *Недоліки:* завжди робить $\frac{n(n-1)}{2}$ порівнянь, навіть якщо масив уже повністю відсортований (час завжди $O(n^2)$); є **нестабільним** алгоритмом (далекий обмін може змінити порядок однакових чисел).
* **Сортування вставкою (Insertion sort):**
  * *Переваги:* **найефективніший** серед елементарних методів на практиці; дуже швидко працює на частково впорядкованих масивах ($O(n)$); є стабільним; може сортувати дані потоково («на льоту»); завдяки простоті використовується в стандартних бібліотеках як базовий випадок для малих масивів.
  * *Недоліки:* у найгіршому випадку (масив у зворотному порядку) вимагає багато операцій зсуву і працює за $O(n^2)$.

### 2. Оцініть кожен з методів відповідно до наступних критеріїв: час роботи, потреби у додатковій пам’яті, стабільність. За якими ще критеріями ви можете порівняти ці алгоритми?

| Алгоритм | Час (Кращий) | Час (Середній) | Час (Гірший) | Додаткова пам'ять | Стабільність |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Bubble sort** | $O(n)$ *(з прапорцем)* | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Стабільний |
| **Selection sort** | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Нестабільний |
| **Insertion sort** | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Стабільний |

* **Час роботи:** Insertion sort та Bubble sort (з прапорцем) на вже відсортованих даних виконуються за $O(n)$, тоді як Selection sort завжди витрачає $O(n^2)$.
* **Пам'ять:** Усі три методи сортують на місці (*in-place*) і вимагають лише кілька допоміжних змінних ($O(1)$).
* **Стабільність:** Bubble sort та Insertion sort зберігають початковий порядок однакових елементів (стабільні). Selection sort може переставити однаковий елемент через інший під час далекого swap (нестабільний).

**Додаткові критерії порівняння:**
1. *Кількість операцій запису в пам'ять:* Selection sort робить лише $O(n)$ обмінів, а Bubble sort та Insertion sort — до $O(n^2)$ зсувів/обмінів.
2. *Адаптивність:* Insertion sort найкраще пристосовується до майже відсортованих даних.
3. *Онлайновість:* Insertion sort може вставляти нові елементи без перезапуску всього алгоритму.
4. *Кеш процесора:* Insertion sort проходить по сусідніх комірках підряд, тому ефективніше використовує кеш процесора (менше cache miss).

### 3. Який випадок є найкращим або найгіршим для роботи цих алгоритмів? (Наприклад: частково відсортований масив або масив, відсортований у зворотному порядку). Який з методів забезпечить у цих випадках найкращий/найгірший результат?

1. **Масив уже відсортований у потрібному порядку:**
   * **Найкращий:** `Insertion sort` та `Bubble sort` (з прапорцем) — обидва зроблять лише $n - 1$ порівнянь і 0 переміщень, час $O(n)$. Insertion sort при цьому швидший за рахунок менших накладних витрат.
   * **Найгірший:** `Selection sort` — все одно виконає всі $\frac{n(n-1)}{2}$ порівнянь ($O(n^2)$).
2. **Частково відсортований масив:**
   * **Найкращий:** `Insertion sort` — зсуває елементи лише на невелику відстань і працює практично за лінійний час $O(n)$.
   * **Найгірший:** `Selection sort` та `Bubble sort` (близько до $O(n^2)$).
3. **Масив, відсортований у зворотному порядку (найгірший випадок):**
   * **Найкращий за записами:** `Selection sort` зробить лише $\lfloor n / 2 \rfloor$ обмінів ($O(n)$).
   * **Найгірший:** `Bubble sort` — зробить максимальну кількість порівнянь і $\frac{n(n-1)}{2}$ повних обмінів swap, через що працюватиме найповільніше.

---

### 4. Що означають позначення O(1), O(n), O(n2)?

Позначення родини **«$O$-велике» (Big O)** вказують на верхню межу того, як швидко зростає час роботи або обсяг пам'яті програми при збільшенні розміру вхідних даних $n$:

1. **$O(1)$ — Константна складність:**
   * Час роботи або пам'ять **не залежать** від розміру масиву $n$.
   * *Приклади:* звернення до елемента за індексом `array[i]`, зчитування довжини `array.length`, оголошення допоміжної змінної `temp` (додаткова пам'ять $O(1)$ у сортуванні).
2. **$O(n)$ — Лінійна складність:**
   * Час роботи зростає **прямо пропорційно** кількості елементів $n$.
   * Якщо збільшити масив у 5 разів — час виконання теж зросте приблизно у 5 разів.
   * *Приклади:* звичайний прохід циклом для пошуку суми чи максимуму, робота `Insertion sort` на вже відсортованому масиві.
3. **$O(n^2)$ — Квадратична складність:**
   * Час роботи зростає **пропорційно квадрату** кількості елементів.
   * Якщо масив збільшити у 2 рази — програма працюватиме у $2^2 = \mathbf{4}$ рази довше; якщо у 10 разів — у $10^2 = \mathbf{100}$ разів довше.
   * *Приклади:* два вкладених цикли, алгоритми сортування `Selection sort`, `Insertion sort`, `Bubble sort` для довільного або реверсивного масиву.
